# 三套演示制作案例

[返回首页](../README.md) · [完整操作指南](USER_GUIDE.md) · [可复制脚本](STORYBOARD.md)

这些是可以手动套用的制作方案，不是应用中已内置的自动模板。参数仅为建议值，实际构图应以预览为准。当前每个工程只有一个视频、一个聚焦区间、一条字幕和一个固定遮挡。

## 案例一：30 秒展示一个核心功能

**目标**：让第一次看到产品的人知道“它解决什么问题”。

适合文件转换、数据筛选、任务创建等能在一个窗口完成的操作。用虚构数据准备好初始页面，避免录制登录和真实客户信息。

### 录制脚本

| 原片时间 | 画面安排 | 操作建议 |
| --- | --- | --- |
| 0–3 秒 | 初始页面 | 等画面稳定，不急着移动鼠标 |
| 3–8 秒 | 输入示例内容 | 提前准备简短输入，避免长时间打字 |
| 8–15 秒 | 执行核心操作 | 停在关键按钮附近，让观众看清 |
| 15–25 秒 | 展示结果 | 保持结果可见，不连续切换页面 |
| 25–30 秒 | 最终状态 | 留出阅读时间后停止 |

### 建议设置

- 画布：16:9；背景：薄荷；留白约 0.07；圆角约 16。
- 标题：`从原始数据，到清晰结果`。
- 标签：`FEATURE WALKTHROUGH`。
- 字幕：`选择条件，立即查看筛选结果`，原片 8–25 秒。
- 聚焦：原片 8–15 秒，约 1.4 倍；焦点对准关键操作所在区域。

不要把 30 秒塞满多个功能。真正要强调的是一次操作及它的结果，而不是整个菜单结构。

## 案例二：20 秒版本更新说明

**目标**：让已有用户看出这次更新增加了什么。

录制 25 秒原片，在前 3 秒准备好页面，之后演示一次新操作；假设最后两秒只是停止录制，可以把成片裁为原片 **3–23 秒**。

| 项目 | 建议 |
| --- | --- |
| 画布与背景 | 16:9，落日 |
| 主标题 | `新增快捷筛选，更快找到目标` |
| 标签 | `RELEASE HIGHLIGHT` |
| 聚焦 | 原片 8–13 秒，对应成片 5–10 秒 |
| 字幕 | 原片 4–21 秒，对应成片 1–18 秒 |
| 字幕文案 | `新增快捷条件：减少重复输入，保留常用选择` |

标题和文案必须符合你展示的软件实际能力。只有一个镜头区间时，优先强调新增入口，之后用正常比例让观众看到结果。

如果操作本身不能在同一段录屏中清楚完成，先简化演示任务，而不是假定应用可以把多段素材拼接起来。

## 案例三：15 秒交互作品展示

**目标**：展示自己有权使用的原型或前端界面的一次关键交互。

选择方形画布方便做作品预览。先把待录制窗口调整到合适尺寸，避免将整张超宽桌面缩成难以辨认的小图。

1. 前 4 秒保持初始状态，展示界面层级。
2. 中间 6 秒完成一次交互，例如打开筛选面板并应用条件。
3. 后 5 秒展示完成状态，给观众时间理解变化。

建议：1:1、夜幕背景、标题 `一个交互，看见设计细节`、聚焦原片 4–10 秒、约 1.3 倍。焦点不要仅对准鼠标，应同时照顾触发控件和变化区域。

方形、竖屏画布不会自动重排网页。若缩小后文字太小，应重新规划录制窗口或改用横屏，不要仅依赖高倍率放大。

## 如何判断成片是否有效

请一个没使用过产品的人看一遍，然后只问三件事：

- 这个功能帮助完成什么任务？
- 关键操作发生在哪里？
- 完成后的结果是什么？

如果对方答不出，先调整内容顺序、文字和停留时间，再考虑增加视觉效果。这里不承诺播放量、转化率或传播效果。
